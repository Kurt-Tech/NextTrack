# NextTrack Pilot Evaluation Procedure

## Purpose

The purpose of the pilot is to verify that the NextTrack user
evaluation procedure is understandable, technically reliable and
practical before conducting the formal participant evaluation.

Pilot responses are intended to improve the evaluation procedure and
interface and will not be combined with the formal participant results.

## Pilot Participants

The pilot will involve one or two testers.

Pilot participant codes should be kept separate from formal study
participant codes.

Recommended pilot codes:

- P901
- P902

These codes also allow both counterbalancing orders to be tested.

## Procedure

1. Provide the participant with the study information and explain the
   purpose of the pilot.

2. Open the NextTrack evaluation interface.

3. Allow the participant briefly to view Explore Mode so that they
   understand the concept of recent tracks, exploration and
   recommendations.

4. Switch to Study Mode.

5. Give the participant their pilot participant code.

6. Ask the participant to select the first study context.

7. Allow the participant to review or listen to the recent tracks.

8. Generate Recommendation Set A and Recommendation Set B.

9. Ask the participant to review both sets. Spotify links may be used
   where additional listening is required.

10. Ask the participant to complete the evaluation questions for that
    comparison.

11. Repeat the process for the remaining study contexts.

12. Record the total time required to complete the study.

13. After completion, ask the participant whether any instructions,
    controls, terminology or questions were unclear.

## Study Contexts

The pilot will test the same three contexts currently configured for
the formal study:

- Rock
- Hip-Hop
- Country

## Controlled Variable

Recommendation Set A and Recommendation Set B use the same:

- recent listening context;
- recommendation algorithm;
- dataset;
- preference settings.

The manipulated variable is exploration level.

The two conditions are:

- exploration level 0.00;
- exploration level 1.00.

The interface does not reveal which condition produced Set A or Set B.

Presentation order is counterbalanced using the participant code.

## Pilot Success Criteria

The pilot is considered successful if:

- the participant can complete the procedure without researcher
  intervention beyond the written instructions;
- both recommendation sets generate successfully;
- Spotify links function sufficiently for evaluation;
- the participant understands the difference between recent tracks and
  recommendations;
- the participant understands how to compare Set A and Set B;
- the hidden experimental condition is not obvious from the interface;
- the questionnaire questions are understandable;
- the study can be completed within an acceptable time;
- no critical interface errors occur.
